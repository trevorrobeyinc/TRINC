## 2. What the engine actually does (the part you said you didn't understand)

You type a research question into **Obsidian Copilot chat**. That hands off to an Obsidian plugin (`openclaw-command-center`) which runs a small local web bridge on port `:8799`. The plugin launches a Node program — `scripts/run-workflow.js` — which is the **OpenClaw research engine**. It runs one of **six biomedical workflow templates** (drug-discovery, pharmacovigilance, clinical-trial-landscape, target-validation, rare-disease, general). For each step it calls a large language model, pulls in biomedical tool data, scans the text for citation identifiers, and — once the citation gate passes — **writes the results back into your Obsidian vault itself** as a set of linked notes (Overview, one note per agent role, Quality Audit, Dataset Card, the four integrity deliverables verbatim, and a deterministic Graph Analysis from the Medical Zettelkasten MCP). That write happens **headless** — it does not need Obsidian open, and the engine runs the same way from a plain terminal. When Obsidian *is* open, the Command Center plugin finds those notes (it never writes them twice) and adds the enrichment stages: the chat bubble, Miyo indexing, the LLM Zettelkasten linking appended to the synthesizer note, and the research-memory ingest. *(Rewired 2026-09-22 — before that the plugin was the only writer, and it only fired for runs it had dispatched itself while Obsidian was open, which had never happened: no run had ever reached the vault.)*

## 3. Citations — what's real, and the one real gap

**Real:** the engine *extracts* citation identifiers with regular expressions (`openclaw-bridge/core/citation-extractor.js`) and embeds them in the notes, and there are quality gates that check citation density before a report is considered done.

**Updated 2026-06-12 — a zero-fabrication CITATION-INTEGRITY layer now ships.** The engine no longer just extracts identifiers; it checks that the cited ones are *grounded in the source records actually retrieved at runtime*, and screens cited DOIs for retraction. What's now live:
- **Runtime grounding gate (report-level).** `agent-engine` persists `fetched_citation_ids` (the identifiers actually retrieved at runtime by tool-prefetch) plus a per-task `citation_verification` block; `buildPrompt` carries an ABSOLUTE-RULE "ZERO FABRICATION" clause (never invent a PMID/NCT/DOI — say "[no verifiable citation found]" instead). `workflow-engine.executeMissionStep` then runs `verifyReportCitations` (`openclaw-bridge/core/citation-gate.js`): every identifier cited in the assembled report is cross-checked against the union of runtime-fetched ids. A cited id is **grounded** if it was in fetched evidence, else **ungrounded** (likely model-introduced). Per the never-hallucinate doctrine (operator ruling 2026-07-10) the gate returns a **three-state verdict**, not a silent boolean: **PASS** (grounded ratio ≥ `minGroundedCitationRatio`, now a required value in `config/agent-config.json` = **0.75**, the B-grade floor); **UNVERIFIED** (`PHASE30_CITATION_UNVERIFIED` — ratio below the floor); **INSUFFICIENT_EVIDENCE** (`PHASE30_CITATION_INSUFFICIENT_EVIDENCE` — **zero runtime evidence was fetched**: a recorded honest-zero that now BLOCKS rather than auto-passing, which is the doctrine hole this ruling closed); and **NO_CITATIONS** (`PHASE30_CITATION_NONE` — evidence fetched but the report cited nothing). Only PASS ships; every non-PASS verdict writes `citation-verification.json` + `report-annotated.md` (surviving ungrounded cites annotated inline `[UNVERIFIED]`). The floor is read **fail-closed** (missing/invalid config → the strict `0.75` default plus a `min_grounded_ratio_unconfigured` warning), replacing the old hardcoded `0.34` / dead `0.5`.
- **Retraction screen — Crossref + PubMed, cross-checked (widened 2026-07-10, escalation + notice-disambiguation same day).** Cited DOIs are checked against Crossref `/works/{DOI}` (`openclaw-bridge/mcp/crossref-retraction/crossref-retraction.js`); cited PMIDs against PubMed E-utilities `esummary` (`openclaw-bridge/mcp/pubmed-retraction/pubmed-retraction.js`, publication type `Retracted Publication`); AND every cited DOI is reverse-resolved DOI→PMID (E-utilities `esearch <doi>[AID]`) and cross-checked against PubMed. A report citing ANY retracted paper hard-stops (`PHASE30_CITATION_RETRACTED`). Fail-soft everywhere: a network error yields no NEW retractions, so a blip can never wrongly block a report. **Per-DOI rule: `retracted = pubmedRetracted OR (crossrefFlagged AND NOT pubmedNotice)`.**
  - **Why all three legs (verified live 2026-07-10 — do NOT "simplify").** Crossref's `update-to`/`relation` signal is **inconsistent and ambiguous**: (1) it is ABSENT on `10.1016/S0140-6736(97)11096-0` (**Wakefield 1998, retracted 2010**) — the DOI screen alone scores the most notorious retraction in medicine as **clean**; PubMed marks it `Retracted Publication`, and the DOI→PMID escalation catches it. (2) It is AMBIGUOUS: `update-to: [retraction]` appears on both the Surgisphere original retracted paper AND the Wakefield **retraction notice** `10.1016/S0140-6736(10)60175-4`, so Crossref alone false-flags the notice. PubMed's pubtype (`Retraction Notice` vs `Retracted Publication`) disambiguates, and a Crossref flag is overridden only when PubMed positively says notice. (3) Many citations carry a **PMID and no DOI** (e.g. GeneReviews, PMID 20301295) and never reach Crossref at all.
  - **Exact-match rule.** Both `Retracted Publication` and `Retraction Notice` are matched **exactly**. Citing a retraction notice is legitimate and must never hard-fail a report; a substring match on "retract" would. Never loosen either to a regex.
  - **Fail-closed on the retraction axis.** Under a PubMed outage a Crossref flag STANDS (conservative — block rather than risk shipping a retraction); the `checked` flag goes false to signal incomplete coverage. This differs from the coverage CLAIM, which fail-softs.
  - **Parenthesized-DOI extraction fix (same day).** The DOI extractor previously excluded `)`, truncating Elsevier/Lancet legacy SICI DOIs (`10.1016/S0140-6736(97)11096-0` → `10.1016/S0140-6736(97`) into a malformed id no registry could screen. It now captures balanced internal parens and trims only an unbalanced trailing `)` from prose wrapping. This is what makes the Wakefield DOI screenable at all.
  - **PMID width fix (same day).** The PMID pattern was `\d{6,9}`, which (a) MISSED legitimate sub-6-digit historical PMIDs — PMID 1 is a real 1975 paper — leaving them invisible to both the grounding gate and the retraction screen, and (b) TRUNCATED a 10+ digit run to a 9-digit prefix that can collide with a different real PMID. Now `\d{1,10}(?!\d)`: covers PMID 1 through 10 digits (centuries of headroom past the current ~41M/8-digit max) and drops an over-long run rather than mis-capturing a prefix. Measured impact on the grounded-ratio denominator across all shipped bundles: **zero** (real reports cite 7–8 digit PMIDs that both patterns already matched) — this is a correctness fix for edge cases, not a scoring change.
  - **Residual gap (honest caveat).** A retracted paper cited **by DOI only, NOT indexed in PubMed**, whose publisher also never deposited a Crossref `update-to`, is still missed. The Retraction Watch bulk dataset (Crossref Labs, ~65 MB) would close it but needs storage + refresh; not built.
- **DOI extraction fix.** The DOI regex now stops at non-DOI terminators and strips trailing sentence punctuation, so `]]` / `;` / `.` are no longer captured (which had deflated the grounded ratio and duplicated DOIs).
  - **Markdown-emphasis fix (2026-09-22, from the first gated run started in Copilot chat).** A citation the model wrote as `**Lynch et al., 2004 (doi: 10.1056/nejmoa040938)**` was captured as `10.1056/nejmoa040938)**` — the `)` sat behind the `**`, so the unbalanced-paren trim never reached it — and the re-resolver sent the literal `)**` to doi.org (404 → UNRESOLVED → the whole run BLOCKED, while the same DOI's plain mention was VERIFIED). `normalizeDoiId` now also trims trailing `*`/`~`; regression test in `tests/core/citation-extractor.test.js`. The other UNRESOLVED id in that run, `NCT07442490`, is a genuine 404 in ClinicalTrials.gov — the gate caught a model-introduced trial id exactly as designed.

**Honest framing (the brand is zero-fabrication):** citations are **grounded in the source records actually retrieved at runtime**, **DOI retraction-screened (Crossref)**, **and — as of the post-research integrity layer — independently re-resolved per identifier against their issuing public registries at delivery time.**

**✅ GAP CLOSED — the resolver is BUILT, WIRED, and VERIFIED (validated 2026-07-10).** The former "only true product-quality hole" no longer exists. What was previously spec'd is now shipping:
- **Resolver.** `openclaw-bridge/mcp/citation-reresolver/citation-reresolver.js` (`RESOLVER_TABLE_VERSION = "2026-06-19"`) re-resolves each cited identifier against its issuing registry: **PMID** → NCBI E-utilities `esummary.fcgi`; **NCT** → ClinicalTrials.gov API v2 `/studies/{id}`; **DOI** → Crossref `/works/{doi}/agency`, with a `doi.org` HEAD fallback. Each id is stamped **VERIFIED / UNRESOLVED / UNCHECKED** with its `http_status` and `resolved_url`. **Fail-soft by construction: a non-definitive answer is UNCHECKED, never a false VERIFIED.**
- **Wiring.** `workflow-engine.js` calls `reresolver.resolveAll(cites)` → `buildReproducibilityManifest()` → writes `reproducibility-manifest.json` + `.md`; `deliverable-packager.js` ships both into `deliverables/` and registers `artifactRefs.reproducibility_manifest`.
- **Delivery decision.** `BLOCK` on any UNRESOLVED id (the fabrication signature), any retracted DOI, or a gate hard-fail; `DELIVER` only at 100% VERIFIED; otherwise `DELIVER_WITH_FLAGS`.
- **Live-run proof.** Real shipped bundle `workspace/releases/offer-2af242bc1548229c102fee55/deliverables/reproducibility-manifest.json`: **34 citations — 29 VERIFIED (85.3%), 0 UNRESOLVED, 5 UNCHECKED** (16/16 DOI, 10/10 NCT, 3/8 PMID), `environment.offline: false`, `delivery_decision: DELIVER_WITH_FLAGS`.

**You MAY now assert per-citation external re-resolution to a buyer** — this supersedes the previous "do not assert" instruction. Assert it with these honest bounds: (1) re-resolution confirms the identifier **resolves to a source record**, not that the source's scientific conclusions are correct; (2) identifiers with no definitive answer are reported **UNCHECKED**, never verified; (3) the re-resolution pass is itself fail-soft — a resolver/network failure logs `citation_reresolution_failed` and the report can ship without a manifest (an UNRESOLVED id, by contrast, hard-fails `PHASE30_CITATION_UNRESOLVED`).
