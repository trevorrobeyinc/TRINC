# Raycast AI → Copilot Plus relay (custom provider)

**Set up and verified live on 2026-10-13.** Raycast AI uses the same model that Obsidian Copilot's
agent mode runs on its **opencode backend**, `copilot-plus/copilot-plus-flash`, plus the other
relay models on the same Copilot Plus licence. It does not spend Raycast AI credits.

> No secrets in this repo. The live config holds the Copilot Plus licence key and stays outside
> git. This repo carries only a copy with the key replaced by a placeholder, and a smoke test that
> reads the key at run time without printing it.

---

## Why

Raycast AI's own credits ran out. On a **paid** Raycast plan (Pro, Pro+ or Max), Raycast v2 lets you
add any OpenAI-compatible provider through `~/.config/raycast/ai/providers.yaml` ("Custom Providers").
Those requests go straight from the Mac to the provider, so Raycast credits are not used. **The Free
plan cannot load custom providers.**

## How Obsidian reaches the model (the chain Raycast copies)

```
Obsidian Copilot  agentMode.activeBackend = "opencode", default model copilot-plus/copilot-plus-flash
  └─ spawns  ~/.obsidian-copilot/opencode/<ver>/bin/opencode acp --cwd <vault>      (ACP over stdio)
       └─ env OPENCODE_CONFIG_CONTENT injects provider "copilot-plus":
            npm @ai-sdk/openai-compatible
            baseURL https://models.brevilabs.com/v1
            apiKey  = the Copilot Plus LICENCE KEY (from Obsidian's keychain, app.secretStorage)
                 └─ POST https://models.brevilabs.com/v1/chat/completions {model: "copilot-plus-flash"}

Raycast AI  →  providers.yaml provider "copilot-plus"  →  the same POST, sent directly
```

Where this is in the fork source (`repos/obsidian-copilot-mcp-v4/src/`):

| Fact | Source |
|---|---|
| opencode is spawned as `opencode acp`, with the provider config passed in `OPENCODE_CONFIG_CONTENT` | `agentMode/backends/opencode/OpencodeBackend.ts` (`buildSpawnDescriptor`, `buildOpencodeConfig`) |
| Copilot Plus is mapped to opencode's provider id `copilot-plus` | `agentMode/backends/opencode/opencodeModelResolve.ts` (`COPILOT_PLUS_OPENCODE_PROVIDER_ID`) |
| *"The license key IS the relay token"* | `modelManagement/setup/CopilotPlusSetupApi.ts` (`registerPlusProvider`) |
| Relay base URL | `constants.ts` (`BREVILABS_MODELS_BASE_URL`) |
| The key lives in Obsidian's keychain, not `data.json` | `modelManagement/providers/ProviderRegistry.ts` (`getApiKey`) |

For this model, **opencode only relays requests**. It adds the agent loop (vault tools, MCP servers),
not the model itself. Raycast gets the model and Raycast's own tools, but not opencode's agent.

**HTTPS-only invariant:** met by construction. No local listener or proxy is involved; Raycast talks
directly to `https://models.brevilabs.com`.

How each setting was chosen:
- **Vision and tools** come from Copilot's own model metadata (`configuredModels[].info`).
- **Context windows** come from the models.dev cache (`~/.cache/opencode/models.json`). Where two
  catalogs disagree, the smaller value is used.
- **`reasoning_effort` is off for every model.** Nothing shows the relay accepts that parameter, and
  Raycast's manual warns that declaring a setting a model doesn't support can make requests fail.
- **Copilot's list and the relay can drift apart.** The model list in `constants.ts` (`ChatModels`)
  is not the same thing as what Brevilabs actually serves.

## Rebuild from scratch (e.g. after a machine wipe)

1. In Raycast, on a paid plan, go to Settings → AI → **Reveal Providers Config**. That creates
   `~/.config/raycast/ai/` and Raycast's own template file.
2. Copy the committed template into place:
   ```bash
   cp "/Users/myhome/TrevClaw-Obsidianodus/Copilot-Everything/configs/raycast/providers.copilot-plus.template.yaml" ~/.config/raycast/ai/providers.yaml && chmod 600 ~/.config/raycast/ai/providers.yaml
   ```
3. **The operator pastes the licence key** in place of `PASTE_COPILOT_PLUS_LICENSE_KEY_HERE`. Get it
   from the Copilot dashboard, or from Obsidian → Copilot settings → the Copilot Plus card. An agent
   never handles this step.
4. Run the smoke test. It prints only the HTTP status and a short reply for each model, never the key:
   ```bash
   python3 -I "/Users/myhome/TrevClaw-Obsidianodus/Copilot-Everything/scripts/raycast-relay-smoke.py"
   ```
5. In Raycast, Settings → AI → Custom Providers should list **Copilot Plus (Obsidian) · 7 models** with
   no "Invalid providers.yaml" badge. Set **Copilot Plus Flash** as the default for AI Chat and
   Quick AI.

Raycast watches the file, so edits take effect immediately without a restart.

## Handling the key

- **Brevilabs issues no per-app key.** The licence key is the only credential, so Obsidian's keychain
  and `providers.yaml` hold the same value.
- **If you rotate the key, update both places.** A missed copy shows up as HTTP 401 in Raycast.
- **Never commit the live file**, and never open it with an agent's file-read tool, because that puts
  the key into the agent's transcript. Change it with a script that never prints the key. That is how
  the `kimi-k2.7-code` entry was removed.
- **TextEdit is fine for pasting the key.** It saved the file as plain UTF-8 YAML, which was verified.
  Don't *type* quote characters in TextEdit, because smart quotes break YAML.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| "Invalid providers.yaml" badge | Hover it for the parse error. The previously loaded models keep working meanwhile |
| HTTP 401 | Licence key rotated or mistyped. Paste it again |
| HTTP 400 `invalid_model` | The relay dropped that model. Remove its entry |
| Web search or read-page refused | Raycast-hosted tools may need Raycast credits. Set `tools: read_page: jina` (no key needed) and drop `web_search` |
| Models listed but every request fails | Run the smoke test first. It separates relay problems from Raycast problems |

## Risks accepted by the operator

- **Terms unverified.** Brevilabs' Copilot Plus terms for using the key outside the plugin could not
  be found (2026-10-13). If the licence were flagged, Obsidian would lose access too.
- **Shared quota.** Raycast and Obsidian draw on one Copilot Plus allowance. Flash is described as
  having "the most quota".
- **No agent features in Raycast.** Raycast gets the model only. Bringing opencode's agent to Raycast
  (vault edits, MCP) would need a Raycast extension driving `opencode run`, which is a separate
  project.

## Fallback lane (not configured)

If the relay rejects Raycast, or the terms risk is dropped, add a second provider using **OpenCode
Zen's free models from zero-retention providers**: Space Bunny Free, LongCat 2.5 Preview Free and
Step 5 Preview Free. Use base `https://opencode.ai/inference/v1` (`/chat/completions`) and a
**dedicated** Zen key created in the OpenCode console, so the opencode CLI's own key is never copied.

Details verified 2026-10-13:
- The free list rotates. Re-check it with `GET /models` before relying on any entry.
- Zen's docs say Big Pickle, Cat Jam, MiMo and Ling free models may use prompts to improve the model,
  and Nemotron says not to send confidential data.
- Muse Spark (`/responses`) and Jev (`/systemone`) don't speak `/chat/completions`, so Raycast can't
  use them.

## Deliberately unchanged

- `~/.config/opencode/opencode.jsonc`, the Copilot plugin, and its `data.json`. Copilot injects its
  own provider config when it starts opencode, so the opencode CLI's `model` default has no effect on
  the Obsidian agent.
- **Seen but not fixed:** the opencode CLI default (`ollama-cloud/minimax-m3:cloud`) points at plain
  HTTP on `:11434`, and Ollama currently serves no models. So the standalone opencode CLI default is
  dead, and it bypasses the `:11435` HTTPS proxy. This is out of scope for this change.
